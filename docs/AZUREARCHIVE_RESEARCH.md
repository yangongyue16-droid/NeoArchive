# AzureArchive 前身调研

更新日期：2026-08-12

## 身份确认

本项目所指的 AzureArchive 是 Foxxlight（狐光体）开发的非官方《蔚蓝档案》剧情编辑器，而不是 `ba-archive/blue-archive` 剧情浏览站。

- 官方文档：https://aadoc.foxxlight.top/
- 问题仓库：https://github.com/foxxdeluxe/AzureArchive-Issues
- 社区剧情项目示例：https://github.com/systemannounce/BA_AAedit

问题仓库已经于 2025-06-15 归档。仓库说明称产品开发进入稳定阶段，后期除严重问题外不再推送更新。

## 已确认能力

官方文档将 AzureArchive 定义为“倾向于还原原生剧情体验”的可视化剧情编辑器。文档明确提到：

- 支持 Windows、Android 与 iOS。
- 支持除纪念大厅播放与视频放映之外的大部分原生剧情功能。
- 提供基于节点的可视化剧情编辑器。
- 面向二次创作的制作、分享与观看。
- 小屏 UI 没有得到充分优化。

社区项目记录显示 2024 年常见版本从 0.7.5、0.7.6.1、0.7.7 迭代到 0.7.8；项目默认保存在 Unity 风格的用户数据目录：

```text
C:\Users\%UserProfile%\AppData\LocalLow\foxxlight\AzureArchive\data\projects
```

社区剧情使用 `.aap` 作为项目文件/目录后缀，并在项目内部保存 `manifest.json`、背景、声音和语音等内容。这说明旧方案偏向“项目自包含资产包”。

## 值得继承的产品原则

1. 剧情编辑与即时预览在同一个工作区完成。
2. 用节点或结构化场景表达演出，而不是让创作者直接写底层代码。
3. 尽可能覆盖原作的对白、角色、背景、音频、转场、选项与特效能力。
4. 一个剧情工程可以独立分享、迁移和播放。

## NeoArchive 应改进的部分

1. **React 组件化界面**：编辑器壳、舞台、属性面板、时间线和资源库拆成明确边界。
2. **数据与素材分离**：剧情 JSON/工程清单进入版本控制，受版权约束的大体积素材通过本地资源库解析，不默认塞进工程包。
3. **开放工程格式**：使用有版本号、可校验、可迁移的 JSON schema，避免依赖不透明的专有结构。
4. **跨平台从 Web 开始**：先把响应式桌面 Web/PWA 做稳，再决定是否封装桌面端；不在第一阶段同时维护三个原生平台。
5. **非破坏式迁移**：为 `.aap` 设计只读导入器，将旧工程转换为 NeoArchive schema，同时保留无法识别的字段和诊断信息。
6. **可维护的 UI**：对话框、按钮和菜单用 React/CSS 实现，游戏纹理只作为可替换装饰层。
7. **大项目性能**：场景列表和节点图应支持虚拟化；预览播放器应隔离高频状态，避免整个编辑器随每帧演出重渲染。

## 建议的第一阶段范围

- 项目创建、打开、保存。
- 场景列表与线性时间线。
- 背景、角色、对白、音频、选项五种基础节点。
- 即时剧情预览。
- 本地资源库映射，不复制素材到发行包。
- 带版本号的工程清单与自动迁移。
- `.aap` 结构探测器，先输出诊断报告，再逐步实现导入。

## 当前技术决策

- React 19 + TypeScript + Vite。
- Vue 参考文件只用于研究，不进入应用实现。
- React 状态按编辑器域、播放器域和资源索引域拆分，避免形成单一全局状态仓库。
- 暂不引入路由、状态库和 UI 框架；等第一个完整编辑流确定后再按真实需求选择。
