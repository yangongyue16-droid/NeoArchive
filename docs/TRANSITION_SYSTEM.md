# 舞台过场系统

## 技术边界

过场属于剧本数据，而不是页面组件中的临时动画。工程使用 `transition.play` Cue 保存预设、总时长、完全遮挡停留时间和强度；Web 与 Tauri 播放器读取同一份数据。

- GSAP 负责可中断、可清理、可重播的时间线编排。
- HTML/CSS 遮罩负责黑白淡化、几何切片、闸门和光环等二维效果。
- PixiJS 继续负责舞台角色；后续只有像素溶解、液态扭曲和复杂滤镜需要进入 Pixi Filter/Shader 层。
- 不引入 ScrollTrigger。播放器过场由剧本事件驱动，与页面滚动无关。
- GSAP 通过动态导入加载，普通编辑和不含过场的播放器首屏不会加载动画包。

## 首批预设

| 预设 ID | 编辑器名称 | 用途 |
| --- | --- | --- |
| `fade-black` | 黑幕淡化 | 时间流逝、章节结束、普通换景 |
| `fade-white` | 白幕闪回 | 回忆、冲击、曝光式切镜 |
| `archive-shutter` | 档案闸门 | NeoArchive 标志性章节切换 |
| `halo-iris` | 光环收束 | 角色聚焦、重要发现、仪式感切换 |
| `chromatic-slice` | 时序轮盘 | 每帧重排圆弧坐标，真实本地日期与时间反向旋转归位 |

后三种构成项目自己的过场语言，不直接复刻原作 UI。每种预设必须在统一的 `StageTransition` 容器中实现，不能侵入对白层、角色层或 Runtime。

## 播放语义

1. Runtime 读到 `transition.play` 后生成新的 `instanceId`，确保同一预设可以连续重播。
2. GSAP Timeline 依次执行进入、完全遮挡、退出；`holdMs` 只控制中间停留。
3. 编辑器只有在当前选中项是过场 Cue 时重播。修改后续对白或角色位置不会重复触发此前动画。
4. 完整播放器仍按 Cue 顺序执行过场，并允许过场覆盖舞台内容但不拦截鼠标事件。
5. 系统检测到 `prefers-reduced-motion` 时直接跳过动画，避免强制闪烁或大幅运动。

### 时序轮盘的剧情时间

`timeWheel` 属于 `transition.play` Cue，并随工程文件保存。它支持两种来源：触发时读取系统时间，或使用创作者填写的剧情日期时间。精度可设为日期、小时、分钟或秒；日期、星期、时间和时区可以分别显示或隐藏。日期精度会自动隐藏时间轮。

轮盘背景保持纯白，不渲染底层网格。日期轮和时间轮每帧重新计算圆弧位置并反向旋转，最终锁定到配置值，而不是使用 CSS 列表平移模拟转动。

## 扩展一个新预设

1. 在 `StageTransitionPreset` 增加稳定 ID。
2. 在 `transitionPresets` 增加中文名称和使用说明。
3. 在 `StageTransition` 增加对应 Timeline 和必要的局部遮罩节点。
4. 同步 Python Pydantic Literal，保证保存、打开和 API 校验一致。
5. 添加 Runtime 重播测试，并在编辑器预览与独立播放器各验证一次。

若新效果需要实时像素采样，再创建 PixiJS Filter；普通遮罩动画仍保留在 DOM 层，避免让 WebGL 舞台承担不必要的纹理开销。
