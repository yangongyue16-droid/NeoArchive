# NeoArchive Galgame 功能设计蓝图

更新日期：2026-08-13

## 1. 设计结论

NeoArchive 不应成为“所有内容都塞进时间线”的视频编辑器，也不应要求创作者手写脚本。更合适的产品形态是：

```text
剧本模式（高频写作）
        ↓ 同一份 Scene/Cue 数据
舞台模式（角色、镜头、音频与时间）
        ↓
流程模式（场景跳转、选择与条件）
        ↓
播放器（与编辑预览共用 StoryRuntime）
```

三种模式只是同一份工程数据的不同视图，不生成三套互相同步的格式。`StoryProject` 仍是工程真相来源，`StoryRuntime` 仍是预览和发布播放器的唯一运行时。

## 2. 核心制作闭环

```text
创建章节/场景
→ 连续输入对白
→ 指定角色、表情、背景和语音
→ 在舞台中调整位置与演出
→ 添加选项和跳转
→ 从当前行即时预览
→ 检查缺失素材与无效分支
→ 保存工程并导出播放器
```

不能直接服务这条闭环的功能，不进入第一阶段。

## 3. 编辑器信息架构

### 3.1 顶层工作区

顶部保留工程名、保存状态、撤销/重做、后端状态和预览按钮，并增加五个入口：

| 工作区 | 主要任务 |
| --- | --- |
| 剧本 | 快速输入、重排和批量编辑对白与指令 |
| 舞台 | 调整角色、背景、镜头、转场和时间 |
| 流程 | 编辑场景跳转、选项和条件 |
| 素材 | 搜索、预览、标记和替换工程素材 |
| 发布 | 校验工程、设置播放器信息并导出 |

默认进入“剧本”。Galgame 制作中最高频的是写对白，舞台调度是第二层任务。

### 3.2 剧本模式

采用“章节/场景树 + 剧本行列表 + 属性面板”三栏结构。每一行对应一条 Cue：

| 行类型 | 行内编辑内容 |
| --- | --- |
| 对白 | 角色、正文、身份、语音、等待继续 |
| 旁白 | 正文、显示方式、等待继续 |
| 角色 | 入场/更新/退场、表情或动画、位置预设 |
| 背景 | 背景素材、转场、持续时间 |
| 音频 | BGM/语音/音效、淡入淡出、循环、音量 |
| 演出 | 镜头、震动、闪白、遮罩、滤镜 |
| 选择 | 提示、选项、条件、目标场景和变量修改 |
| 控制 | 等待、跳转、变量操作、结束章节 |

高频键盘操作：

- `Enter`：在当前对白后新建对白。
- `Shift + Enter`：正文换行。
- `/`：打开“背景/角色/选择”等指令选择器。
- `Cmd/Ctrl + Enter`：从当前行预览。
- `Cmd/Ctrl + D`：复制当前行。
- 上下方向键：在剧本行间移动焦点。

剧本模式默认按执行顺序组织内容，不显示毫秒级时间轴；只有需要精确同步的 Cue 才显示延迟值。

### 3.3 舞台模式

采用“对象列表 + 16:9 舞台 + 时间线 + Inspector”，支持：

- 角色拖动、缩放、翻转、层级与位置预设。
- 最多三名主要角色的左/中/右布局，高级模式允许自由定位。
- 当前说话人高亮，其他角色自动变暗或降低饱和度。
- Spine 动画、表情、入场和退场预览。
- 背景缩放、平移、模糊和淡入淡出。
- 镜头推拉、平移、轻微摇晃和聚焦。
- BGM、语音、音效独立轨道。
- 从选中 Cue 开始预览。

时间线只负责“演出同步”，不承担剧本组织。

### 3.4 流程模式

流程图只显示 Scene，不显示 Scene 内的每条 Cue。节点包括场景标题、首句摘要、背景缩略图、出口和诊断状态。

选择项和条件分支显示为带标签的边；普通线性剧情沿用 `nextSceneId`，不要求创作者连接每个普通场景。

## 4. Galgame 播放器

### 4.1 第一阶段

- 逐字显示；首次点击立即显示完整文本，再次点击进入下一句。
- 自动播放，等待时间由文本长度和语音时长共同决定。
- 已读快进，只跳过玩家看过的对白。
- 对话历史，可重播单句语音。
- 隐藏 UI、暂停、设置和返回标题。
- BGM、语音、音效三个独立音量。
- 选项选择与场景跳转。
- 快速保存、快速读取和普通存档槽。
- 读取后恢复背景、角色、对白、变量和游标。

### 4.2 第二阶段

- 回退到上一句，并恢复当时的舞台和变量快照。
- CG/场景回想、章节选择和已读率。
- 自动语音、语音结束后继续和语音重播。
- 文本速度、自动播放间隔、窗口透明度等偏好。
- 全屏、窗口比例和键盘/手柄快捷键。

## 5. 数据模型演进

### 5.1 角色与素材定义

```ts
type CharacterDefinition = {
  id: string;
  displayName: string;
  subtitle?: string;
  color?: string;
  portraitRef?: string;
  modelRef?: string;
  defaultAnimation?: string;
  aliases?: string[];
};

type AssetReference = {
  id: string;
  kind: "background" | "character" | "voice" | "bgm" | "sfx" | "effect" | "ui";
  source: "project" | "library";
  locator: string;
  hash?: string;
};
```

对白 Cue 应保存 `characterId`，不重复保存角色显示名；允许单条对白覆盖显示名，以支持匿名角色或特殊称谓。

### 5.2 变量与条件

条件不能保存为可执行 JavaScript 或 Python 字符串，应使用可校验的结构化表达式：

```ts
type StoryValue = string | number | boolean;

type Condition =
  | { op: "eq" | "neq" | "gt" | "gte" | "lt" | "lte"; variableId: string; value: StoryValue }
  | { op: "and" | "or"; conditions: Condition[] }
  | { op: "not"; condition: Condition };

type VariableOperation =
  | { op: "set"; variableId: string; value: StoryValue }
  | { op: "increment"; variableId: string; value: number }
  | { op: "toggle"; variableId: string };
```

选择项增加 `visibleWhen`、`enabledWhen` 和 `operations`；场景出口增加带条件的跳转。这样能实现好感度和事件旗标，并在导出前静态检查类型。

### 5.3 建议新增 Cue

| Cue | 作用 |
| --- | --- |
| `narration.show` | 无角色名的旁白 |
| `character.focus` | 当前说话人高亮和其他角色弱化 |
| `voice.play` | 与对白 ID 绑定的语音，支持历史重播 |
| `camera.move` | 镜头平移、缩放、聚焦 |
| `effect.play` | 闪白、震动、遮罩、滤镜等预设效果 |
| `variable.apply` | 执行类型安全的变量操作 |
| `jump` | 条件或无条件跳转 |
| `scene.end` | 结束、返回标题或进入下一章节 |

动画变化继续由 `character.update` 表达，不为每一种动画建立新的 Cue 类型。

## 6. 运行时状态与存档

下一阶段将“舞台投影”和“剧情上下文”分开：

```text
RuntimeState
├── cursor：sceneId / cueIndex
├── story：variables / visitedScenes / readDialogueIds
├── stage：background / characters / dialogue / effects / camera
├── audio：bgm / voice / sfx
└── mode：playing / waiting / auto / skipping / paused / completed
```

存档包含工程 ID、内容版本、游标、变量、舞台、BGM、时间、对白摘要和截图路径。Runtime 显式生成纯 JSON `SaveSnapshot`，读取时校验版本并恢复；不能直接序列化 JavaScript 类实例。

“已读记录”和“玩家设置”属于用户级数据，不随单个存档槽回滚。

## 7. 编辑命令系统

所有工程修改统一进入命令层，UI 不直接修改嵌套对象：

```text
AddScene / RenameScene / MoveScene / DeleteScene
AddCue / UpdateCue / MoveCue / DuplicateCue / DeleteCue
SetSceneExit / AddChoice / UpdateCondition
RegisterAsset / ReplaceAsset / RemoveAsset
CreateCharacter / UpdateCharacter
```

每条命令包含 ID、时间、描述和可逆补丁。连续输入同一段对白时合并历史记录，避免每个字符占用一次撤销。

## 8. 校验与诊断

发布检查至少覆盖：

- 入口场景不存在或不可达。
- 跳转目标不存在；意外终点或无交互死循环。
- 条件引用未定义变量或类型不匹配。
- 素材、Spine 动画或语音缺失。
- Cue、Scene、角色 ID 重复。
- 选择项没有目标或操作。
- 文本为空、角色未定义。
- 使用了不允许打包的研究素材。

诊断分为错误、警告和提示；点击诊断必须跳转到对应场景和 Cue。

## 9. 原型实施顺序

### P0：可制作线性剧情

1. 章节与场景新增、重命名、排序和删除。
2. 剧本行新增、编辑、复制、排序和删除。
3. 背景、角色、对白、旁白、音频和等待六种行类型。
4. 角色定义与素材选择器。
5. 从当前行预览、撤销/重做、保存与打开工程。
6. 播放器逐字显示、自动播放、历史和音量设置。

验收：不编辑 JSON，可以完成并保存一段包含背景、两名角色、对白、语音和 BGM 的线性剧情。

### P1：可制作分支 Galgame

1. 选择行、场景跳转和流程图。
2. 布尔、数字、字符串变量与结构化条件。
3. 存档、读档、快速保存、已读记录和已读快进。
4. 工程诊断、缺失引用跳转和导出检查。
5. 镜头与基础效果预设。

验收：可以制作至少两个结局，并根据选择或变量进入不同分支；存档读取后结果一致。

### P2：表现与扩展

1. 回退、CG/章节回想和章节选择。
2. 本地化表、字幕导入导出和文本统计。
3. 自定义效果预设、插件 Cue 注册和迁移 API。
4. 多角色复杂构图、口型同步和精细音频混合。

## 10. 暂缓功能

- 在线协作、账号系统、社区和素材市场。
- 应用内完整代码编辑器。
- 把每条 Cue 都显示为流程节点。
- 任意 JavaScript/Python 表达式条件。
- 完整视频剪辑、视频导出或复杂粒子编辑器。
- 自研音频或渲染引擎。

## 11. 下一版界面原型

下一轮先实现“剧本模式”，当前舞台成为可切换的“舞台模式”：

1. 顶部加入剧本/舞台/流程/素材/发布入口，先启用剧本与舞台。
2. 当前场景列表升级为章节折叠树，启用新增场景。
3. 中央剧本区渲染所有 Cue 行，而不只展示第一条对白和第一名角色。
4. 加入行选择、`+ 对白`、指令选择器和对应 Inspector。
5. 从选中行预览，并让舞台模式读取同一份 Scene/Cue。

### 剧本式 Timeline

- 对白不填写毫秒时间，以垂直模块的先后顺序播放。
- 背景、角色、音频、等待和过场与对白使用同一模块流，可直接拖拽到任意对白之间。
- 普通模式由玩家点击推进；AUTO 模式优先使用 `Scene.autoAdvanceMs`，未设置时根据对白长度自适应。
- schemaVersion 1 的 `atMs` 保留用于兼容旧文件，不在新编辑器中暴露。
- 背景模块以实际淡入动画的 `animationend` 作为下一模块的起点。
- 角色入场模块依次执行“入场前等待 → Spine 资源就绪 → 入场动画”，入场动画完成后才继续对白。
- 跨场景过场只会在遮罩下准备新场景的首帧背景，不会提前挂载角色或执行后续模块。
6. 将直接编辑函数迁移到通用 `executeCommand` 入口。

完成这一层后，再做流程图和变量系统，避免基础编辑尚未稳定时被分支逻辑拖复杂。
